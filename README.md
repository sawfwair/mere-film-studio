# Mere Film Studio

Mere Film Studio is the native macOS control room for turning one idea into a
reviewed short film with Pi and local `mere.run` media models.

The application is intentionally not another agent harness. Pi directs the
creative process, `mere.run` owns the local provider and model-server lifecycle,
`mere-film-tools` owns durable production state, and this app composes those
layers into one visual, playable control room.

## Product loop

1. Start with one sentence.
2. Resolve only material creative requirements with Pi.
3. Review treatment, canon, screenplay, and shot plan.
4. Approve explicit production gates.
5. Watch local images, video, voices, sound, and music arrive.
6. Compare takes and request targeted rerolls.
7. Review technical and creative evidence before picture lock.
8. Deliver a checksum-backed master or hand it to Animatic for editorial work.

## Build

Requires Apple Silicon macOS, Xcode 26 or newer, and XcodeGen. The generated
application intentionally targets `arm64`; GhosttyKit and the local model stack
are not packaged as Intel compatibility slices.

```bash
brew install xcodegen
./scripts/check.sh
open MereFilmStudio.xcodeproj
```

For the native Ghostty surface:

```bash
brew install anyzig
./scripts/bootstrap-ghostty.sh
./scripts/generate-project.sh
```

Ghostty is pinned and built locally. Generated frameworks and upstream sources
are never committed.

## Package

Create a release build, apply an ad-hoc local signature, verify the complete app
bundle, and produce a drag-to-Applications disk image:

```bash
./scripts/package-app.sh
```

Artifacts land in `.build/release/`. The ad-hoc signature is intended for local
development and direct testing.

For public distribution, select the Developer ID certificate by fingerprint and
reuse the saved notary profile from `mere-run-release-tools`:

```bash
SIGN_IDENTITY=<developer-id-sha1> \
NOTARIZE=1 \
RELEASE_TOOLS_ROOT=../mere-run-release-tools \
./scripts/package-app.sh
```

That path enables the hardened runtime, signs nested frameworks before sealing
the app, notarizes and staples the app, creates and signs the DMG, then notarizes
and staples the disk image. Credentials remain in the release toolchain's
keychain profile and are never copied into this repository.

## Runtime requirements

- `mere-film-tools`
- Pi (`pi`); MereRun-managed installations under Application Support are
  discovered automatically and can be overridden in Settings
- a `mere.run` build with `agent status` and `agent start --inline` support
- FFmpeg and FFprobe
- `animatic` only when publishing a handoff

The Delivery workspace offers a no-write verification pass before the explicit
push. The handoff is generated by `mere-film-tools`, then independently checked
by Animatic for current project identity, contiguous timing, safe paths, entity
references, exact byte counts, and SHA-256 digests before any API write.

The app runs outside the Mac App Store sandbox so it can start these local,
user-installed production tools. It does not read or store provider secrets.
For the embedded room, the app reads `mere.run agent status`, selects the
highest-tier installed startable model, asks `mere-film-tools` for the exact Pi
film-harness command, and passes that command to `mere.run agent start --inline`.
The selected `mere.run` and Pi executables are resolved independently from
project data, so a stale project-local command cannot replace either runtime.
